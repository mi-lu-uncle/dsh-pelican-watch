# 界面方案原型（一次性，已归档）

`panel-redesign.html` 是鹈鹕监视面板的 4 个界面方案原型：用 `?variant=A|B|C|D` 切换，
底部浮动栏可用 `←`/`→`（或 1–4）翻转，并能切换「就绪 / 检测中 / 无数据」三种状态与深浅主题。
数据取自真实 `settings.json` 与实测耗时，画作是内联占位 SVG。

## 结论（2026-10-16）

采用 **A + B「最新作品」 + C「排名」的融合**：

- **A 的左栏模型清单** —— 状态点 / 分数 / 趋势，点击即筛选；
- **B 的最新作品 hero** —— 大图 + 分数压在图上，右侧「最新几张」小图堆；
- **C 的智商排行榜** —— 排名 / 当前分 / 趋势 / 走势 / 次数 / 平均耗时 / 失败 / 状态，可收起；
- 下方保留原有画册网格（A 的密度）。

未采用：方案 D（KPI 卡片 + 奖牌焦点榜）。

融合后的正式实现见 `lib/client.js`（main 分支）。原型本身只留在本分支，不进主线：
main 的 `.gitignore` 忽略了 `prototype/`。

## 第二个问题：能不能「全部平铺、零点击」？（2026-10-16）

`panel-flat.html` — `?variant=E|F|G|H`，底部浮动栏 / `←` `→` / `1-4` 切换，另有
「渲染 SVG / 整页」「主题 深/浅」「数据 正常/检测中/空」三组开关。
数据仍是真实选中项与实测耗时（flash 145s/88 分、vision-exp 132s/94 分、v4-flash 超时）。

| 方案 | 结构 | 需要的滚动 |
| --- | --- | --- |
| E 一屏看板 | 每模型一列：分数、趋势、走势线、最新一张 + 最近 5 张 | 恰好 1 屏，不滚动 |
| F 模型横幅 | 一模型一条带：左边全部指标，右边它画过的每一张 | 1.4 ～ 1.6 屏 |
| G 数据墙 | 上：每一次检测的完整表格（含失败行）；下：全部画作的墙 | 1.2 ～ 1.7 屏 |
| H 轮次对比 | 一行一轮：同一轮里各模型并排，直接看谁降智 | 2.6 ～ 2.9 屏 |

几何验证（无头 Chrome，1500×900 与 1280×800）：4 方案 × SVG/整页 × 深/浅主题
**均无横向溢出**；12 张画同时全部在屏上；面板正文里**不含任何 `button`/`onclick`**
（这条零点击断言写在冒烟测试里，24 个组合全绿）。

截图见 `shots/`（`flat-E/F/G/H.png`，另有 `flat-F-light.png`）。

采用哪个方案：**F（模型横幅）**。已按 F 重写正式插件的 `lib/client.js`，随
**v0.4.0** 发布（commit `a09ce7a`，main 分支）。

落地时做的一处取舍：F 把「查看」做到零点击，但**选模型**、**立刻检测**、
**打开某张画的原始页面**仍然是动作，塞进只读看板里就破坏了这个方案的本意。
所以正式插件把它拆成两半 ——

- 主面板（侧边栏图标进去的那页）：F 布局，**不含任何 button / onClick**，
  纯查看，和原型一致；
- 「设置 → 鹈鹕监视」：同一套 F 看板 + 动作（选择模型、全部检测一遍、单模型
  立刻检测、点某张画打开沙箱化的原始页面）。

原型里的 F 是把这两半的内容都画在一起的；正式实现按上面拆开，其余
（模型横幅的左右分栏、指标块里的哪些数字、画作网格的密度）与 F 一致。

落地后新增的渲染测试又抓出两个真问题并修掉：跑过但从没出图的模型原本显示
绿色「正常」（重启后错误表是空的），现在显示琥珀色「没出图」；一张画都没有时
原本只显示空态、把每个模型的状态和失败原因全藏了，现在提示语放在横幅**上方**
而不是取代它们。
