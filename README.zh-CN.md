# @mi-lu-uncle/dsh-pelican-watch

[English](README.md) | 简体中文 | [日本語](README.ja.md)

一个 DeepSeek Harness（DSH）**社区插件**：按固定间隔对**任意多个模型**运行**长期降智探针**。

- **自己挑模型** — 面板右上角「设置」里的「检测的模型」会列出各 provider 提供的全部模型（实时调 `/models` 发现，并合并你 DSH profile 里已配置的模型），可多选；每个模型走自己的 provider 与 API Key。
- **定时作画** — 每 30 分钟（可配置）让每个已选模型画一个**会动**的「鹈鹕骑车」：单文件 HTML，画面是内联 SVG，动效必须是 SVG 声明式动画（`<animate>` / `<animateTransform>`）。
- **不用技能、不用工具** — 每次都是裸的 `chat/completions` 请求：不带工具定义、不走 agent 循环，测的只是模型本身，和你的本地技能无关。
- **全部平铺、零点击** — 主面板是只读的：每个模型一条横幅，左边是它的状态和指标（最新一张的时间、跑了几次、平均耗时、没出图几次，以及失败原因），右边是它画过的每一张，一次铺满整页 —— 不折叠、不筛选、不需要点任何东西。
- **跑动状态在顶部** — 检测中直接显示「已完成 n/m」「正在检测哪个模型」「已等 m:ss」「超时上限 m:ss」，一眼分清「慢」和「卡住」。
- **动作就在面板右上角** — 一个「设置」按钮弹出面板内的设置窗：挑模型、暂停/恢复自动检测、改间隔、停止本轮；「全部检测一遍」就在它左边。**只想测一个模型**时，点它那条横幅上的「单独检测」：只发一个请求，不动其它模型，也不等别的模型跑完（可以同时点好几个）。看板本身只负责展示，不看设置也能读到全部信息。点任意一张画只是把它放大 —— **只有图，没有文字**。
- **随时停、随时改间隔** — 面板右上角「设置」里可以直接**暂停/恢复自动检测**、改**检测间隔**（1–1440 分钟）、以及**停止正在跑的这一轮**（正在进行的请求会被立刻中断，还没开始的模型直接跳过、不再发请求）。暂停会立刻写入 `settings.json`，重启也保持暂停 —— 只想手动测的时候，一分钱 token 都不会自动花。
- **有界历史** — **每个模型**默认保留最新 10 张，旧的自动清理；这个额度不会被同时在检测的几个模型瓜分，同名模型在不同 provider 下也各存各的。同一道题、同一个模型、坚持几天，退化会直接体现在结构变差、拒画（会保存并标上「未检出 SVG」）、或耗时变长上。

## 安装

推荐从 GitHub 仓库安装：

```sh
dsh plugin --profile desktop add https://github.com/mi-lu-uncle/dsh-pelican-watch.git
```

也支持本地路径或 tarball：

```sh
dsh plugin --profile desktop add /absolute/path/to/dsh-pelican-watch
```

注意：以 `link:` 方式安装的插件不走 HMR 监听，修改 `lib/index.js` 或 `lib/client.js` 后需要重启 App 才能生效。

## 选择模型

面板右上角「设置」里的「检测的模型」会列出 **DSH 里注册的每一个提供方**（包括登录后的「DeepSeek 账号」、官方 API Key 路由、以及你在 profile 里配的第三方 provider），以及每个提供方公布的全部模型，按提供方的显示名分组。勾选任意多个后点**保存模型**——从下一个周期起，每个选中的模型各画一张，并在看板上各占一条横幅。

**看板只显示当前选中的模型**，顺序就是列表里的顺序（不随检测跳动）。取消勾选某个模型并保存，**它的历史画作会被一并删除** —— 看板上不再显示的画，留在磁盘上只会变成看不见的垃圾；这份存档本来就是可以重画的探针记录。

**模型名不是唯一身份**：同一个 `deepseek-flash` 可能同时由「DeepSeek 账号」和某个第三方 provider 提供。所以一条横幅对应的是「provider + 模型」，模型名旁边会标出提供方的显示名（`DeepSeek 账号` / `DeepSeek` / `taotoken`…）——两个 provider 永远不会共用一条横幅，也不会串到对方的画。

插件本身不碰任何密钥：调用走的是 DSH 的模型服务（`ctx.llm`），凭据由 DSH 解析 —— 所以「DeepSeek 账号」这种没有 API Key、只靠登录的提供方也能直接检测，第三方 provider 只要在 DSH 里能用，这里就能选。某个提供方列不出模型（没登录、key 失效）时，它仍会出现在列表里并写明原因。

这份选择存在 `dir/settings.json`，调度器以它为准；`config.model` / `config.targets` 只用于第一次运行的初始值。每轮最多探测 12 个模型，**`concurrency` 个同时进行**（默认 3 个），每个模型各画一张。

同一个 `settings.json` 里还存着两个「花钱」开关，改它们不用动配置文件，直接在面板右上角「设置」里操作：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `autoEnabled` | `true` | 关掉后定时器立刻停摆（`nextRunAt` 变空），只有手动「全部检测一遍」才会花钱；重启后保持关。 |
| `intervalMinutes` | 跟随 `config.intervalMinutes`（30） | 面板上改完立即按新间隔重新计时，不用重启。 |

两个键都会在**校验通过后**才生效：比如一次请求里同时给了合法的 `autoEnabled` 和非法的间隔，整条请求会被拒绝，运行中的调度不会被改一半。

## 速度与超时

- **模型并行检测**（默认同时 3 个）：一个慢模型不再拖住其他人——每张画一画完就落盘，几秒内出现在面板里。
- **每个请求有独立超时**（`timeoutSeconds`，默认 600 秒）。超时只在**它自己**那条横幅上显示「超过 N 秒没有返回」，不会卡住整轮。推理型模型确实可能很慢——同一 provider 实测：`qwen3.7-max` 约 52 秒、`deepseek-flash` 约 121 秒（其中 1.5 万 token 是"思考"），而 `glm-5.3-flash` 有时超过 4 分钟。
- **超时或 HTTP 报错不算画**：既不落盘也不计入出图，因为那是基础设施问题、不是模型表现。而模型**答了却没画**（拒答）会被保存下来、标成「没出图」——那才是值得看的信号。
- 默认**不发送** `maxTokens`：推理型模型动笔前可能花掉几万 completion token，卡一个上限只会把 SVG 截断，并不会更快。

## 配置

默认值贴合常见配置；如需覆盖，在 profile 补丁（`cordis.patch.yml`）的 `pelican-watch` 行上设置：

```yaml
- id: pelican-watch
  config:
    # 初始选择（面板里选过之后以面板为准）
    provider: deepseek-account           # DSH 的提供方路由；默认 deepseek-account
    model: deepseek-flash                # 模型 id
    # targets:                           # 可选：一次给多个模型做初始值
    #   - { provider: deepseek-account, model: deepseek-flash }
    #   - { provider: taotoken, model: glm-5.3-flash }
    intervalMinutes: 30                  # 作画间隔
    maxImages: 10                        # 每个模型保留最新几张（1–100；30 分钟一张 ≈ 5 小时）
    timeoutSeconds: 600                  # 单个请求超时（5–3600）；想更快失败可调小
    concurrency: 3                       # 同时检测几个模型
    # maxTokens: 8192                    # 可选；默认不发送（见下文）
    dir: ~/.dsh/pelican-watch            # 保存目录
    runOnStart: true                     # 启动后 ~8 秒先画一轮
    # temperature: 0.7                   # 可选；默认不带该参数
    # prompt: …                          # 万不得已才改基准题面
```

基准提示词是刻意固定的——改了它历史就不可比了，所以 `prompt` 请当作最后手段。

提示词要求动效必须用 SVG 声明式动画（`<animate>` / `<animateTransform>`），这不是偏好：面板用 `<img>` 显示提取出来的 SVG，浏览器在"SVG 当图片"时**不播放 CSS 动画、也永远不执行脚本**，只有 SMIL 会动。如果是自己改提示词，`<style>` 里的 `@keyframes` 或 `<script>` 驱动的动画都会变成静止画面。

## 凭据

这个插件**没有**自己的 API Key 配置：它通过 DSH 的模型服务（`ctx.llm`）调用模型，凭据完全由 DSH 解析——API Key 路由用它自己存的 key，`deepseek-account` 用你登录的账号。所以：

- 想检测哪个模型，先在 DSH 里让那个提供方可用（设置 → 模型），这里就能直接选；
- 换 key、重新登录都不用改插件配置；
- 面板和接口里**不会出现任何密钥**（插件根本不读它）。

调不通时面板会按失败原因说人话：`需要先在 DSH 里登录 DeepSeek 账号`、`这个提供方还没有配置凭据`、`被限流了`、`额度不足`、`超出模型的上下文窗口` 等。

## 只展示，不打分

这个插件**不评分**。它只做两件事：按节奏让每个模型画同一道题，然后把画原样摆在面板上。

早期的版本会离线算一个 0–100 的「结构分」（有没有 SVG、车轮、车架、翅膀……），已按要求移除 —— 分数只能近似"画里有没有出现这些元素"，反倒容易给人一个虚假的精确感。现在判断交给看图的人（或看图模型）：**同一道题、同一个模型、连续几天，画本身的变化就是结论**，不需要任何数字替你做判断。

面板上剩下的数字都不是评分，只是事实：跑了几次、平均耗时、最近一张的时间、没出图几次。`没出图` 指的是这一次请求回来了但没有可用的 SVG（典型的拒答），它照样会被保存到磁盘上（面板不渲染那段文字）。

## 存储

画保存在 `dir`（默认 `~/.dsh/pelican-watch`）：

| 文件 | 作用 |
|---|---|
| `<时间>_<模型>.html` | 生成的完整页面；首行是元信息注释（模型、provider、时间、耗时、是否检出 SVG） |
| `<时间>_<模型>.svg` | 抽取出的内联 SVG，供面板 `<img>` 预览使用 |
| `settings.json` | 已选中的探测目标（由选择器写入）+ 两个节奏开关 `autoEnabled` / `intervalMinutes` |

手动删除这里的文件是安全的；面板永远以磁盘上的现状为准。

## 隐私与安全

- 所有路由与其他插件一致，做了同源校验。
- 画作只以 `image/svg+xml` + `x-content-type-options: nosniff` + `default-src 'none'` 的 CSP 返回，并且只通过 `<img>` 展示：模型围在 SVG 外面的那段说明文字、markdown 围栏、以及任何 `<script>` 都不会被渲染，模型输出不可能在 App 源里执行。没有任何路由把存档页面当 HTML 发出来。

## 布局

| 文件 | 作用 |
|---|---|
| `lib/index.js` | Host 半：多模型调度器、调度控制、存储、`/api/pelican-watch/*` 路由（模型调用走 `ctx.llm`，不碰密钥） |
| `lib/client.js` | Client 半：平铺看板（每个模型一条横幅 + 它的全部画作）+ 右上角「设置」窗（React） |
| `cordis.patch.yml` | Bundle 补丁，把本包作为一个 host 行挂载 |
| `package.json` | npm 元数据 + `dsh.bundle`/`dsh.client`/`dsh.compatibility` |
| `test/pelican.test.mjs` | 离线测试：按模型汇总、provider 解析、目标选择、调度控制、路由接线 |
