# @mi-lu-uncle/dsh-pelican-watch

[English](README.md) | [简体中文](README.zh-CN.md) | 日本語

DeepSeek Harness（DSH）向けの**コミュニティプラグイン**：固定間隔で**任意の数のモデル**に対して**長期のモデル品質（劣化）プローブ**を実行します。

- **モデルは自分で選ぶ** — パネル右上の「設定」→「検出するモデル」は、**DSH に登録されているすべてのプロバイダ**（ログイン済みの「DeepSeek アカウント」、公式 API キーのルート、プロファイルで設定した第三者プロバイダ）と、それぞれが公開している全モデルを、DSH の表示名でグループ化して一覧表示します。複数選択できます。
- **定時作画** — 30 分ごと（設定可能）に、選択した各モデルへ**動く**「自転車に乗るペリカン」を描かせます：単一 HTML ページ、インライン SVG、動きは SVG の宣言的アニメーション（`<animate>` / `<animateTransform>`）で実装させます。
- **スキル・ツール不使用** — 毎回 `chat/completions` の素のリクエストです。ツール定義なし、エージェントループなし。測るのはモデルそのもので、ローカルスキルには依存しません。
- **すべて平置き・クリック不要** — メインのボードは読み取り専用です。モデルごとに 1 本のバンドを出し、左側に状態と数値（最新作の時刻、実行回数、平均所要時間、作品が返らなかった回数、失敗理由）、右側にそのモデルが描いたすべての作品を一度に並べます。折りたたみも絞り込みもなく、クリックは一切不要です。
- **実行状況はヘッダーに** — プローブ中は「完了 n/m」「どのモデルを実行中か」「待ち時間 m:ss」「タイムアウト上限 m:ss」を表示し、「遅い」と「固まっている」を一目で区別できます。
- **操作はパネル右上の 1 ボタン** — パネル自身の右上にある「設定」ボタンが設定シートを開きます：モデル選択、いますぐプローブ。作品をクリックすると拡大表示になりますが、**画像だけで文字は出ません**。ボード側は表示専用のままで、読むためにクリックは不要です。**1 つのモデルだけ**試すときは、そのバンドの「単独で検出」を押します：そのモデルに 1 本だけリクエストを送り、他のモデルは消費しません（複数のバンドを同時に走らせることもできます）。
- **いつでも止められる・間隔を変えられる** — 同じ設定シートから**自動プローブの一時停止 / 再開**、**検出間隔**（1〜1440 分）の変更、**実行中の 1 周期の停止**ができます。実行中のリクエストは即座に中断され、まだ開始していないモデルはリクエストを送らずにスキップされます。一時停止は `settings.json` に即保存され再起動後も維持されるため、手動でしか実行しない運用なら勝手にトークンを消費しません。
- **有界な履歴** — **モデルごとに**最新 10 枚を保持します（設定可能）。同時にプローブしているモデル同士で枠を分け合うことはなく、同じモデル id を別プロバイダが提供していても履歴は別々に保たれます。同じお題・同じモデルを数日続けると、劣化は構造の悪化、拒否（保存され「SVG なし」バッジが付く）、所要時間の増大として現れます。

## インストール

GitHub リポジトリからのインストールを推奨します：

```sh
dsh plugin --profile desktop add https://github.com/mi-lu-uncle/dsh-pelican-watch.git
```

ローカルパスや tarball でも可能です：

```sh
dsh plugin --profile desktop add /absolute/path/to/dsh-pelican-watch
```

注意：`link:` 方式でインストールしたプラグインは HMR 監視の対象外のため、`lib/index.js` や `lib/client.js` を編集した後はアプリの再起動が必要です。

## モデルの選択

パネル右上の「設定」→「検出するモデル」に一覧が出ます：DSH に登録された全プロバイダ（ログイン済みのアカウント、公式 API キーのルート、第三者プロバイダ）と、それぞれが公開するモデルです。任意の数をチェックして**モデルを保存**すると、次の周期から選択した各モデルが 1 枚ずつ描き、ボードにそれぞれ 1 本のバンドを持ちます。

**モデル名は一意ではありません**：同じ `deepseek-flash` を「DeepSeek アカウント」と第三者プロバイダの両方が提供することがあります。バンドは「プロバイダ + モデル」の組で、モデル名の隣にプロバイダの表示名（`DeepSeek アカウント` / `DeepSeek` / `taotoken`…）が出ます。2 つのプロバイダがバンドを共有することも、描いた絵が混ざることもありません。

プラグインはキー素材に一切触れません：呼び出しは DSH のモデルサービス（`ctx.llm`）経由で、クレデンシャルは DSH が解決します。だから API キーを持たずログインだけで動く「DeepSeek アカウント」もプローブでき、DSH で使えるプロバイダはここでもそのまま使えます。モデル一覧を取得できないプロバイダ（未ログイン、キー失効）も、理由付きで一覧に残ります。

この選択は `dir/settings.json` に保存され、スケジューラはこれを正とします。`config.model` / `config.targets` は初回のみの初期値です。1 周期で最大 12 モデルを、**`concurrency` 個同時に**（デフォルト 3）プローブし、各 1 枚ずつ描きます。

同じ `settings.json` に、消費を左右する 2 つの設定が入ります（設定ファイルを触らず、パネル右上の「設定」から変更できます）：

| キー | 既定 | 意味 |
| --- | --- | --- |
| `autoEnabled` | `true` | オフにするとタイマーが即座に外れ（`nextRunAt` が空に）、手動の「今すぐプローブ」だけが消費します。再起動後もオフのままです。 |
| `intervalMinutes` | `config.intervalMinutes`（30）に従う | パネルで変更すると即座に新しい間隔で再スケジュールされます（再起動不要）。 |

## 速度とタイムアウト

- **モデルは並列実行**（デフォルト 3 同時）なので、遅いモデルが他を待たせません。描き上がった作品はその場でディスクに保存され、数秒以内にパネルに現れます。
- **リクエストごとに独立したタイムアウト**があります（`timeoutSeconds`、デフォルト 600 秒）。超えたモデルは**そのモデル自身の**バンドに「N 秒を超えて応答なし」と表示され、周回全体を止めません。推論モデルは実際に遅いことがあります — 同じプロバイダでの実測：`qwen3.7-max` 約 52 秒、`deepseek-flash` 約 121 秒（うち約 1.5 万トークンが思考）、`glm-5.3-flash` は 4 分を超えることも。
- **タイムアウトや HTTP エラーは作品ではありません**：保存もされず、作品としても数えません（インフラ側の事象でありモデルの振る舞いではないため）。一方、**答えたが描かなかった**（拒否）場合は保存し「作品なし」と表示します — こちらが見るべきシグナルです。
- `maxTokens` はデフォルトで送信しません：推論モデルは描き始める前に数万 completion トークンを消費することがあり、上限を設けても速くならず SVG が切れるだけです。

## 設定

デフォルトは一般的な構成に合わせてあります。上書きする場合はプロファイルパッチ（`cordis.patch.yml`）の `pelican-watch` 行で指定します：

```yaml
- id: pelican-watch
  config:
    # 初期選択（パネルで選ぶとそちらが優先）
    provider: deepseek-account           # DSH のプロバイダルート（既定はアカウント）
    model: deepseek-flash                # モデル id
    # targets:                           # 任意：複数モデルを初期値にする
    #   - { provider: deepseek-account, model: deepseek-flash }
    #   - { provider: taotoken, model: glm-5.3-flash }
    intervalMinutes: 30                  # 作画間隔
    maxImages: 10                        # モデルごとに保持する枚数（1〜100。30 分間隔なら約 5 時間）
    timeoutSeconds: 600                  # リクエストごとの上限（5〜3600）。早く失敗させたいときは短く
    concurrency: 3                       # 同時にプローブするモデル数
    # maxTokens: 8192                    # 任意。デフォルトでは送信しない（下記参照）
    dir: ~/.dsh/pelican-watch            # 保存ディレクトリ
    runOnStart: true                     # 起動後約 8 秒で最初の 1 周を描く
    # temperature: 0.7                   # 任意。デフォルトではパラメータ自体を送らない
    # prompt: …                          # ベンチマーク文面の変更は最終手段
```

ベンチマークのプロンプトは意図的に固定しています。変更すると履歴の比較ができなくなるため、`prompt` は最終手段と考えてください。

動きは SMIL でなければなりません。これは好みではなく制約です：パネルは抽出した SVG を `<img>` で表示し、ブラウザは「SVG を画像として」扱うとき **CSS アニメーションを再生せず、スクリプトも実行しません**。動くのは宣言的 SMIL だけです。`@keyframes` や `<script>` で動かした絵はここでは静止して見えます。

## クレデンシャル

このプラグインは**独自の API キー設定を持ちません**。DSH のモデルサービス（`ctx.llm`）経由で呼び出すため、クレデンシャルは DSH が解決します：API キーのルートは DSH が保存したキーを、`deepseek-account` はログイン中のアカウントを使います。したがって：

- プローブしたいモデルは、まず DSH 側（設定 → モデル）でそのプロバイダを使える状態にしてください。それだけでここで選べます；
- キーの入れ替えや再ログインでプラグイン設定を変える必要はありません；
- キーがパネルや API に出ることはありません（プラグインは読みません）。

失敗時はパネルが理由を人間の言葉で示します：`需要先在 DSH 里登录 DeepSeek 账号`、`这个提供方还没有配置凭据`、`被限流了`、`额度不足`、`超出模型的上下文窗口`。

## 表示のみ・採点なし

このプラグインは**採点しません**。やることは 2 つだけ：決まった間隔で全モデルに同じお題を描かせ、その作品をそのままボードに並べる。

以前のバージョンはオフラインで 0〜100 の「構造スコア」を算出していました（SVG があるか、車輪・フレーム・翼があるか…）。これは要望により削除しました。その数字は「これらの要素が現れたか」を近似できるだけで、むしろ根拠のない精度感を与えてしまいます。判断は絵を見る人（または画像を見られるモデル）に委ねます：**同じお題・同じモデルを数日続ければ、絵そのものの変化が結論**であり、数字に代弁させる必要はありません。

ボードに残る数値は評価ではなく事実です：実行回数、平均所要時間、最新作の時刻、作品が返らなかった回数。`作品なし` は「応答は返ったが使える SVG が無かった」（典型的には拒否）を意味し、生の応答は保存されているので読むことができます。

## ストレージ

作品は `dir`（デフォルト `~/.dsh/pelican-watch`）に保存されます：

| ファイル | 役割 |
|---|---|
| `<時刻>_<モデル>.html` | 生成されたページ本体。先頭行にメタコメント（モデル・プロバイダ・時刻・所要時間・SVG 検出の有無） |
| `<時刻>_<モデル>.svg` | 抽出したインライン SVG。パネルの `<img>` プレビュー用 |
| `settings.json` | 選択中のプローブ対象（ピッカーが書き込み）+ ペース設定 `autoEnabled` / `intervalMinutes` |

ここにあるファイルを手動で削除しても安全です。パネルは常にディスク上の実態を表示します。

## プライバシーと安全性

- すべてのルートは他のプラグインと同様に同一オリジン検証を行います。
- 作品は `image/svg+xml` + `x-content-type-options: nosniff` + `default-src 'none'` の CSP で返し、`<img>` 経由でのみ表示します：SVG の外側にある説明文、markdown フェンス、`<script>` は一切レンダリングされず、モデル出力がアプリのオリジンで実行されることはありません。保存ページを HTML として返すルートは存在しません。

## 構成

| ファイル | 役割 |
|---|---|
| `lib/index.js` | Host 側：マルチモデルのスケジューラ、スケジュール制御、ストレージ、`/api/pelican-watch/*` ルート（モデル呼び出しは `ctx.llm` 経由、キーには触れない） |
| `lib/client.js` | Client 側：平置きボード（モデルごとに 1 バンド + 全作品）と、右上の「設定」シート（React） |
| `cordis.patch.yml` | このパッケージを 1 つの host 行としてマウントするバンドルパッチ |
| `package.json` | npm メタデータ + `dsh.bundle`/`dsh.client`/`dsh.compatibility` |
| `test/pelican.test.mjs` | オフラインテスト：モデル別集計、対象選択、スケジュール制御、ルート配線（偽の `ctx.llm` で駆動） |
